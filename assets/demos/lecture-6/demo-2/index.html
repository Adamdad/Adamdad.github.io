    01Causal attention

    Every new token looks back at all of its history.

    Token i may attend to tokens 1…i and nothing after. Each row of the score matrix is one query; each filled cell is one query–key score.

    ✎ Pause & predict

    The context doubles from 8 to 16 tokens. The number of attention scores grows by about…

    About 4×. There are n(n+1)/2 scores: 36 for n = 8 and 136 for n = 16. Pairs grow with the square of the context, which is why long contexts get expensive fast.

    02Recomputing the past

    Old keys and values never change.

    Without a cache, every step re-projects K and V for the whole prefix — even though token 3’s K and V are identical at step 3 and at step 12. Step through and click a token to see it.

    ✎ Pause & predict

    At step 9, how many of the 8 earlier tokens have K/V that changed since step 8?

    None. Causal masking means token i only ever sees tokens ≤ i, so its K and V depend on nothing that arrives later. They are the same at every step.

    Without a cache, almost all of the work is repeated work.

    3
    03The KV cache

    Keep the past. Compute only the new row.

    Store each token’s K and V once (hatched = reused). At each step project just the new token, append its K and V, and let the new query read all cached keys. The text is identical; the work is not.

    ✎ Pause & predict

    With a KV cache, is the attention step itself free?

    No. The cache saves the old K/V projections, not the new token’s attention: the new query still takes a dot product with every cached key, so each step is still O(n).

    The cache skips old work — not the new token’s attention.

    04The price of the cache

    The cache trades compute for memory.

    Every cached token stores a K and a V in every layer. Memory grows with context length and with the number of sequences (or beam paths) kept alive. Pick a model size and drag.

    ✎ Pause & predict

    We double the context and double the batch. KV memory becomes…

    4×. KV memory ∝ context length × number of sequences. Doubling each multiplies the product by 2 × 2.

    KV memory ∝ context length × active sequences.

    5
    05Prefill and decode

    Prefill once, then one token at a time.

    The prompt is processed in parallel (prefill) and produces token 1. Every later token is a separate decode step. Three numbers describe a request: TTFT, inter-token latency (ITL), and end-to-end latency (E2E).

    ✎ Pause & predict

    Does a KV cache make the first token (TTFT) arrive faster?

    No. The first token needs the whole prompt processed once, with or without a cache. The cache speeds up the decode steps (ITL, and so E2E), not the prefill.

    Toy timings with the right shapes (prefill ∝ prompt, cached step ≈ constant, uncached step ∝ context) — not benchmarks.

    Takeaway

    The cache speeds up decode (ITL, E2E) — TTFT still pays for the prompt.

    Long chat or document?n large

    Decode is fast, but one sequence’s cache can take gigabytes — memory is the limit.

    Many users at once?batch × n

    Memory multiplies with every active sequence; serving systems budget the cache like a resource.

    Wide beam search?B paths

    Each beam path keeps its own history, so B paths cost about B× the cache.
